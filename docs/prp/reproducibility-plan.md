## Proposed independent comparison

1. Use independently accepted r3 as the first complete baseline build; compilation, helper inspection and the separate actual-output audit passed. Interrupted r2 has no accepted images. Preserve that accepted build's complete record, logs, resolved `.config`, input snapshot, image hashes and installed-package inventory. Record public signing identities and the effective make/package epochs without displaying or copying private keys.
2. Establish the signing-input policy before the second build. Fresh default APK keys are an expected source of differing bytes. Reusing signing inputs would require a separately reviewed method for handling sensitive material and matching provenance; this plan supplies none and performs no key access. Disabling signing or changing reproducibility options would create a different configuration and requires two new matched builds, not comparison against the first accepted complete build. Matching a public key alone also does not prove deterministic signatures.
3. Create an independent fresh source/feed/build workspace from the verified baseline; reuse no compiled objects, staging trees or generated outputs. Use immutable image `sha256:96695425b78f34c79f71e4500c7565f968095abae933c40da35a0d8e0584e5ec`, the exact full source/feed commits, byte-identical resolved config, verified command-line-enforced epoch (selected manifest value 1792282260), and recorded tool/package inventory. Reuse only verified source downloads if explicitly recorded; hash every reused archive. Compare the image identity, inventories, environment allowlist, commands, code hashes and source/input records before compiling.
4. Use the same eight-job command and stable in-container build path/user/hostname for the initial comparison. Mount the independent host workspace at the same container path; leave the original workspace preserved and unmounted. Record all identity/path inputs and any intentional differences. A later path-variation experiment is a separate, stronger test; do not enable debug remapping or change kernel identity options silently.
5. Inspect both outputs independently. Compare SHA-256 and byte lengths for every emitted GL-XE3000 factory/sysupgrade image and named auxiliary artifact. Compare package names/versions/architecture, rootfs/public-key identities, profiles metadata, embedded board/target/revision metadata and config/feed/version buildinfo. Keep all original bytes; record comparisons in a separate report. Auxiliary-artifact equivalence is distinct from permission to flash them.
6. If hashes differ, first compare recorded inputs, effective epochs and signing identities, then metadata, archive ordering/timestamps, rootfs files, kernel/toolchain objects and embedded paths. Use local comparison tools such as diffoscope on non-secret copies; exclude private-key paths and avoid dumping arbitrary generated files into reports. Report differing components and unresolved causes without replacing image hashes with normalized hashes.
7. Claim only the exact scope demonstrated: byte-identical named images under the recorded inputs/environment, with any signing-material dependencies stated. Matching package inventories or unsigned payloads alone is a narrower result. Require independent review of the comparison and preserved-baseline checks; keep `reproducible=false` until that evidence supports changing it. Hardware, recovery and production acceptance remain separate gates.
