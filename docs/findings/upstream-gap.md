## Acceptance gates for a reproducible recipe

These gates define subsequent local build work. They do not authorize flashing, bootloader installation or router commands.

1. **Evidence and scope:** complete sanitized stock triangulation with provenance and uncertainty recorded for each unresolved row. Retain the completed S5/S6 extraction coverage limits and unresolved evidence requirements. Decide which experiments are justified; unresolved modem/MCU behavior remains explicitly experimental.
2. **Clean baseline:** create a separate clean checkout pinned to the full commit above, or document and review a deliberate replacement pin. Preserve the existing dirty checkout and untracked work. Record baseline identity and exact patch series; verify clean application and ensure shared-DTS effects are intentional.
3. **Manifest:** supply a project recipe containing full source/feed revisions, feed configuration, patch hashes/order, seed and resolved configuration, overlay inventory, build commands, toolchain/compiler and host/container identity. Record input checksums and expected output names. Pin downloaded inputs or verify their hashes.
4. **Configuration and patch tests:** verify patch application against the clean pin; resolve configuration and assert `mediatek/filogic` plus `glinet_gl-xe3000` selection. Check intended MHI/USB/QMI/MBIM modules and userspace in the resolved config and package manifest. Assert that placeholder-only MCU packaging cannot satisfy a functional MCU gate.
5. **Build verification:** complete the build in the recorded environment; retain concise logs, exit status, resolved config, package manifest, artifact inventory and SHA-256 checksums. Inspect image metadata/device compatibility and compare expected output names and contents. A successful build establishes buildability only. Rebuild independently and compare artifacts/checksums before claiming bit-for-bit reproducibility; explain any differences.
6. **Artifact boundary:** distinguish firmware images from generated preloader/FIP artifacts in the manifest and review output. Confirm **no bootloader artifacts were installed** and no router changes occurred during recipe/build verification. Exclude bootloader installation from the recipe workflow.
7. **Separate hardware acceptance:** retain a distinct future gate for storage/identity preservation, modem/SIM behavior, MCU/thermal/charging behavior and recovery/rollback validation. Passing local build gates must not mark those hardware gates complete.
